# 余韻を別ストリームで保持するループ

Android の通常再生・ループ編集の試聴、Windows/Linux の再生は、同じ
`TailLoopRenderer` と `MidiLoopStream` を使用する。UI、設定の保存形式、
ライブラリやプレイリストの保存形式は変更していない。

## 音声経路

```text
MIDI デコーダー A ─┐
                   ├─ stereo float 加算 ─ PCM 出力1本 ─ デバイス
MIDI デコーダー B ─┘
```

2本の MIDI デコーダーは同じ SoundFont ハンドルを共有する。次周用のデコーダーを
事前に戻り先へシークしておき、境界の PCM フレームで役割を交代する。
次周のアタックを早めたり、ループの時間をクロスフェード分だけ短縮したりはしない。

旧デコーダーにはシークしない。ファイルから来るイベントをフィルターで遮断し、
サステイン・ソステヌートを解除して All Notes Off を送る。All Sound Off や
System Reset は送らない。旧ボイスのリリースと内蔵リバーブ／コーラスを
そのままレンダリングし、次周の音声に加える。`DECAYEND` は旧デコーダーの
ファイル終端後も余韻を得るために使用する。`DECAYSEEK` によるループは使用しない。

余韻の上限は **2秒とループ区間の半分の短い方**。末尾の最大50msでゼロまで
フェードし、その後に旧デコーダーをリセット・シークして次の交代に備える。
したがって非常に短い区間でもストリーム数は増えない。ループ境界での
ファイルオープン、SoundFont ロード、ネイティブストリームの作成・解放はない。

最大発音数の設定は各 MIDI デコーダーに適用する。重なっている間は旧音分の
発音数と CPU 使用量が増える。次周の音量を下げる正規化は行わないため、
重なりによってピークが増える場合がある。

## 制御と寿命

- 一時停止、音量、曲終端フェードは共通の PCM 出力に作用し、余韻も一緒に制御する。
- 手動シークと停止では両方のデコーダーと PCM 出力バッファをリセットする。
  デコード専用ストリームの内部リバーブも消去するため、再利用時を含め
  デコーダーのシークには `BASS_POS_FLUSH` を明示する。
- ループ点の編集では旧設定の余韻を破棄し、待機側を新しい戻り先へ準備する。
- ロックの順序はホストのモニター → BASS 出力チャネル → MIDI デコーダー。
  音声コールバックからホストや `MidiLoopStream` の制御メソッドを呼ばない。
- 解放時は出力を先に解放し、実行中の音声コールバックが戻ってから
  両 MIDI デコーダー、最後に SoundFont を解放する。JNA/JNI のコールバック参照も保持する。
- 音声コールバックでの例外はネイティブ側へ送出せず、出力を終了し、エラーを記録する。
- 表示位置は出力の消費済みフレームを MIDI 上の位置に対応付ける。
  Android のループ通知もこの位置を50ms間隔で確認し、先読みした境界では通知しない。
- Android の通常の次曲移行は PCM 出力の再生時刻の END 同期で実行する。
  マーカー付き曲の有限ループ後の8秒フェードは維持する。
  BASS の属性フェードは停止中にも進むため、一時停止・停止・手動シークで
  進行中の自動フェードと古い次曲移行要求を無効化する。

## 自動検証

Windows の実行例（JDK 21 と既存の依存キャッシュ）:

```powershell
$env:JAVA_HOME = 'C:/Program Files/Android/Android Studio/jbr'
$env:GRADLE_USER_HOME = 'D:/2by2MusicPlayer/.gradle-user'
./gradlew.bat :app:assembleDebug :app:testDebugUnitTest :shared:testDebugUnitTest :shared:desktopTest :desktopApp:test --offline --console=plain
```

- `TailLoopRendererTest`: 境界の正確なアタック位置、ステレオ加算、短区間の多数回ループ、
  再生位置と先読みの分離、手動シーク、ループ無効化、不正な区間。
- `MidiLoopStreamLifecycleTest`: 音声生成中の解放待ち、二重解放防止、初期化失敗時の
  回収、コールバック例外の封じ込め、両音源への設定適用。
- `NativeTailTest`: 同梱 BASS/BASSMIDI と生成した SoundFont による無音出力の実測。
  後続のノート・強制停止イベントの遮断、EOT を越えるリリース、独立したリバーブ、
  次周の無音部分への余韻の加算、シーク後の無音、100回ループの位置、同梱150曲の境界。
- 既存の共有コード・デスクトップのテストも実行する。

## 実機で聴き比べる項目

実際の GUI・可聴再生はユーザーが確認する。自動検証は音声経路の性質を確認するもので、
すべての曲・SoundFont で聴感上の継ぎ目がなくなることを保証するものではない。

1. Android 通常再生・編集試聴、Windows/Linux で同じ曲と SoundFont を使用する。
2. リバーブの長い曲、弦やパッド、サステイン、ドラム、CC111 あり／なしを聴き比べる。
3. 短いループを繰り返し、テンポのずれ、音量の過度な上昇、音の蓄積がないか確認する。
4. 余韻中の一時停止／再開、停止、シーク、曲切替、SoundFont 切替、終了を確認する。
5. Android の音声フォーカス喪失・イヤホン切断と、有限ループ後の次曲移行を確認する。

戻り先より前に Note On がある持続音の完全な状態再現は別の課題として残る。
今回保持するのは旧音源の余韻であり、任意位置の完全なシンセサイザー状態の複製ではない。
